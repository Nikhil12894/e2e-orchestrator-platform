## Shipped Requirements

### Execution Response Navigation URLs

- [x] **EXEC-01**: Execution trigger endpoint (`POST /api/v1/workflows/{id}/execute`) returns an HTTP `Location` response header matching `statusUrl`, and the response body contains absolute `statusUrl`, `reportUrl`, and `streamUrl` navigation URLs resolved against the incoming request origin (including reverse-proxy headers like `X-Forwarded-Host` and `X-Forwarded-Proto`).
  - *Outcome:* Validated in Phase 3. Implemented via `ExecutionNavigationUrlBuilder` and Spring's `ForwardedHeaderFilter`.
- [x] **EXEC-02**: Execution details endpoint (`GET /api/v1/executions/{id}`) and list endpoint (`GET /api/v1/executions`) return populated absolute navigation URLs (`statusUrl`, `reportUrl`, `streamUrl`) reflecting the request origin.
  - *Outcome:* Validated in Phase 3. Controller endpoints dynamically enrich `WorkflowExecutionEntity` responses.
- [x] **EXEC-03**: Completed or failed execution details queried via `GET /api/v1/executions/{id}` provide the populated `reportUrl` pointing directly to the generated Karate HTML report endpoint (`/api/v1/executions/{id}/report/workflow-report.html`).
  - *Outcome:* Validated in Phase 3. `ExecutionNavigationUrlBuilder.buildReportUrl` links directly to static report assets.

### Synchronous Wait Execution Mode

- [x] **SYNC-01**: Execution trigger endpoint supports a `?wait=true` query parameter with configurable `timeoutSec` (default 60s, defensively clamped 1s-300s) to block until execution completes on the virtual thread.
  - *Outcome:* Validated in Phase 4. Virtual thread carrier unmounting via `CompletableFuture.get()`.
- [x] **SYNC-02**: When `?wait=true` completes within timeout, the API returns HTTP 200 containing the completed execution entity, final `ExecutionStatus` (`COMPLETED` or `FAILED`), and generated `reportUrl`.
  - *Outcome:* Validated in Phase 4. Covers success, failures, and cancellations.
- [x] **SYNC-03**: When `?wait=true` exceeds `timeoutSec`, the API responds gracefully with HTTP 504 Gateway Timeout (or 202 status via `timeoutStatus=202`) with `X-Execution-Timed-Out: true` header indicating background continuation without failing the running execution.
  - *Outcome:* Validated in Phase 4. `TimeoutException` handled without cancelling background tasks.

### Sub-Workflow Chaining & Global Variable Promotion

- [x] **SUBWF-01**: Dynamic Global Header Variable Resolution — `DynamicKarateBridge.computeEffectiveHeaders` dynamically resolves `${variableName}` expressions from `globalContext` on every HTTP step, so variables extracted by preceding steps (or sub-workflows) automatically populate global default headers (e.g. `Authorization: Bearer ${authToken}`).
  - *Outcome:* Validated in Phase 5. Bridge re-evaluates flow headers per HTTP request.
- [x] **SUBWF-02**: Pre-requisite / Setup Workflow in Global Workflow Settings — `WorkflowSettingsModal` and AST schema support configuring an optional pre-requisite workflow that executes prior to the canvas steps, binding its output variables directly into `globalContext`.
  - *Outcome:* Validated in Phase 5. Synthetic setup step prepended at index 0 in `DynamicKarateRunner`.
- [x] **SUBWF-03**: Canvas Sub-Workflow Quick-Add & Variable Badges — Visual canvas displays variable export chips on `SubWorkflowNode` indicating exported variables, with autocomplete support in the configuration drawer.
  - *Outcome:* Validated in Phase 5. Amber Zap badges rendered on node; Sparkles suggestion chips in drawer.
- [x] **SUBWF-04**: Standalone Feature Export Parity — `TestWorkflowService.generateStandaloneKarateFeature` generates dynamic Karate header evaluation functions (`configure headers = function() { ... }`) that read from `context`, preserving 100% execution parity in offline / CI terminal runs.
  - *Outcome:* Validated in Phase 5. JavaScript dynamic callback generated for `defaultHeaders` and `dynamicHeaders`.

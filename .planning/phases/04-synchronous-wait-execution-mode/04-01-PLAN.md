<objective>
Enable CI/CD pipelines, automated scripts, and cURL clients to synchronously await workflow test execution results via `POST /api/v1/workflows/{id}/execute?wait=true&timeoutSec=N`.

Purpose: Provide blocking execution semantics on Java 25 Virtual Threads so automated pipelines can obtain final execution status (`COMPLETED` or `FAILED`) and direct Karate HTML report URLs in a single HTTP request without polling loops, while defending against connection starvation and ensuring long-running executions continue in the background upon client timeout.
Output: `ExecutionSyncResult.java` DTO, synchronous execution methods in `TestWorkflowExecutionService`, query parameter handling and timeout logic in `WorkflowExecutionController`, configuration defaults in `application.yml`, and comprehensive integration test suite `WorkflowExecutionSyncModeTest.java`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → WorkflowExecutionController | Untrusted HTTP clients (cURL, CI/CD runners, browser) supply query parameters (wait, timeoutSec, timeoutStatus) and execution payload |
| WorkflowExecutionController → TestWorkflowExecutionService | Request thread parks on Java 25 virtual thread awaiting background execution completion |
| TestWorkflowExecutionService → DynamicKarateRunner | Background virtual thread executing Karate scenarios and writing results/reports |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Denial of Service | `WorkflowExecutionController` (`timeoutSec` query param) | high | mitigate | Clamp `timeoutSec` defensively between 1 second and `maxWaitTimeoutSec` (default 300s). Java 25 Virtual Threads unmount OS carrier threads during `CompletableFuture.get()`, preventing platform thread starvation. |
| T-04-02 | Tampering | `TestWorkflowExecutionService` & `WorkflowExecutionController` | high | mitigate | When `timeoutSec` expires, catch `TimeoutException` without cancelling the task or setting cancellation flags in `DynamicKarateBridge`. Background virtual thread continues execution and writes report to disk and database. |
| T-04-03 | Information Disclosure | `DynamicKarateRunner` & `ExecutionNavigationUrlBuilder` | medium | mitigate | All secrets in context snapshots are masked using `ExecutionLogBroadcaster.maskSecrets()` and `DynamicKarateRunner.sanitizeContextSnapshot()` before entity persistence and JSON serialization. |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero new third-party dependencies are introduced. All functionality is implemented using JDK 25 standard library (`CompletableFuture`) and Spring Boot 4.1.2. |
</threat_model>

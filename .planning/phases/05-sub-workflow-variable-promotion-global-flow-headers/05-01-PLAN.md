<objective>
Implement dynamic global flow header resolution, pre-requisite setup workflow execution, and standalone Karate feature export parity on the backend execution engine.

Purpose: Allow workflows to execute authentication and setup sub-workflows, extracting tokens and identifiers into global context, which are reactively evaluated in global flow headers for all downstream HTTP steps across both in-memory virtual thread execution and exported standalone Karate features.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Variable Context -> Header Evaluation | User-extracted variables from preceding steps cross into HTTP request header values |
| Setup Workflow Reference | User-configured workflow ID in setupWorkflow config references an external workflow entity |
| AST to Standalone Feature Export | AST default headers and step configs are compiled into executable Karate Gherkin and JavaScript |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Tampering / Info Disclosure | `DynamicKarateBridge.computeEffectiveHeaders` | medium | mitigate | Variable substitution resolves tokens only against active and global execution context maps; does not evaluate arbitrary expression languages or external commands |
| T-05-02 | Denial of Service | `DynamicKarateRunner.java` | high | mitigate | Prevent circular infinite recursion by asserting setup workflow ID is not equal to parent workflow ID and validating call depth in DynamicKarateBridge |
| T-05-03 | Tampering / Code Injection | `TestWorkflowService.generateStandaloneKarateFeature` | high | mitigate | Escape quotes, backslashes, and special characters when generating standalone Karate JavaScript header functions to prevent JS injection |
| T-05-SC | Tampering | Build & Dependency Management | high | mitigate | Package legitimacy gate: verify all Maven dependencies against project POM without introducing unvetted external libraries |
</threat_model>

Enrich workflow execution responses with first-class navigation URLs (`statusUrl`, `reportUrl`, `streamUrl`) and standard RFC 7231 `Location` response headers, dynamically adapted to incoming request schemes, hosts, ports, and reverse proxy headers.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client / Reverse Proxy → WorkflowExecutionController | Untrusted HTTP headers (Host, X-Forwarded-Host, X-Forwarded-Proto) cross into controller origin resolution |
| HTTP Request → Report Asset File System | URL path parameters cross into local file path resolution for Karate HTML reports |
| REST API → External Consumers (cURL, CI/CD) | Outgoing execution payload and Location header returned to unauthenticated / authenticated callers |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | ForwardedHeaderFilter / application.yml | medium | mitigate | Enable server.forward-headers-strategy: framework so Spring's ForwardedHeaderFilter validates forwarded host syntax and normalizes proxy headers safely per RFC 7239 |
| T-03-02 | Tampering | WorkflowExecutionController.serveReportAsset | high | mitigate | Restrict relativeFile path using contains("..") check and enforce targetFile.startsWith(reportDir) boundary check before serving files |
| T-03-03 | Information Disclosure | ExecutionNavigationUrlBuilder | low | mitigate | Generate navigation URLs containing only resource UUIDs (/api/v1/executions/{id}) and standard report paths without embedding query secrets, tokens, or environment values |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero new dependencies introduced in Phase 3; all implementations use existing Spring Boot 4.1.2 and TypeScript libraries |
</threat_model>

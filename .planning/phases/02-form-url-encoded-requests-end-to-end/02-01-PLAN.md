Implement the end-to-end dynamic execution tracer slice for form URL-encoded HTTP requests per FORM-03:
1. In HttpRequestStepConfig.java, add private field bodyType initialized to "JSON", and private field formData initialized to a new LinkedHashMap. Add getters and setters for bodyType and formData. Add helper method boolean isFormEncoded() returning true if "FORM_URL_ENCODED".equalsIgnoreCase(bodyType) or if headers map contains Content-Type matching "application/x-www-form-urlencoded" (ignoring case).
2. In MockTargetApiController.java, add a mock authentication endpoint @PostMapping(value = "/auth/token", consumes = org.springframework.http.MediaType.APPLICATION_FORM_URLENCODED_VALUE) annotated with @Operation. Bind @RequestParam Map formParams. Return a ResponseEntity containing a map with access_token (prefixed mock-token-), token_type "Bearer", expires_in 3600, username (extracted from formParams or defaulting to "guest"), and received_fields (the input formParams map).
3. In execute-http.feature, replace the unconditional request call with conditional branching:
   - Define isForm checking (httpCfg.bodyType == 'FORM_URL_ENCODED') or mergedHeaders Content-Type / content-type == 'application/x-www-form-urlencoded'.
   - Define formPayload as isForm ? (httpCfg.formData || httpCfg.body || {}) : null.
   - Define reqBody as (!isForm and httpMethod is not get and httpMethod is not delete) ? httpCfg.body : null.
   - Conditionally invoke * if (isForm) form fields formPayload.
   - Conditionally invoke * if (!isForm && reqBody != null) request reqBody.
   - In Bridge.onStepFinished call, pass isForm ? formPayload : httpCfg.body as effective request payload.
4. In WorkflowFeaturesAndPortabilityTest.java, create testDynamicKarateExecutionFormUrlEncoded: build a TestWorkflowEntity with an HTTP step configured with method POST, url pointing to /api/v1/mock/auth/token, bodyType FORM_URL_ENCODED, and formData containing username and grant_type. Execute via karateRunner.executeWorkflow and assert finished execution status is ExecutionStatus.COMPLETED with 200 HTTP response.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External Runner → Exported Gherkin | Exported .feature files run on external CI environments with variable substitutions |
| AST Step Config → Gherkin Generator | Step parameters from canvas/AST (form keys, values, secret tokens) are serialized into Gherkin text |
| Dynamic Bridge → Mock API Controller | In-memory execution sends form-urlencoded data to target HTTP services |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `TestWorkflowService.java:formatFormFieldsExpression` | high | mitigate | Format `${$secret:VAR}` and `${$env:VAR}` tokens using `formatKarateExpression` into dynamic environment lookups (`karate.properties['VAR'] \|\| java.lang.System.getenv('VAR')`) rather than embedding raw secret strings into exported feature files. |
| T-02-02 | Tampering | `backend/src/main/resources/karate/execute-http.feature` | high | mitigate | Use Karate's native `form fields` keyword which guarantees RFC 3986 percent-encoding and parameter separation rather than raw string concatenation. |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | Package legitimacy gate verified in RESEARCH.md; no external package additions required. |
</threat_model>
